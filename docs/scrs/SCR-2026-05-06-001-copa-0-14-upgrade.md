## Revision 2 (2026-05-08) — Strategic Redirect

### Why this SCR was revised

Phase B local smoke surfaced a failure mode (`cockroachdb/cockroach`: `go mod download ... no modules specified`) that pointed at a deeper issue. Investigation of the fork-vs-upstream diff revealed:

- `github.com/project-copacetic/copacetic` v0.14.0 and `github.com/verity-org/copacetic` `feat/go-vcs-resolution` are **diverged** (status: `diverged`, ahead_by=12, behind_by=12).
- Common merge base: upstream commit `2f6cc54` (BuildKit pin, pre-v0.14.0).
- The fork carries **12 commits** authored by Omer (2026-04-11 to 2026-04-25) that are **not** in v0.14.0:
  - Fallback source resolution for stripped Go binaries (commit 1) — a more developed version than upstream PR #1546
  - OCI label source resolution (commit 3)
  - Trivy report data fallback when Go binary detection fails on distroless (commit 5) — addresses cockroach-class images
  - Binary-paths-from-stdlib-updates fix (commit 6) — addresses the exact `no modules specified` failure mode
  - Trivy Target binary path extraction + GoVersion synthesis (commit 7)
  - Intermediate Solve verification before claiming rebuild success (commit 8)
  - OpenTelemetry module derivation lookup table (commit 10)
  - Plus review-feedback iterations (commits 2, 4, 9, 11) and a merge of upstream main from 2026-04-29 (commit 12)
- Total fork-only footprint: ~600 lines net across `pkg/langmgr/golang.go`, `pkg/provenance/rebuilder.go` (+220), `pkg/provenance/rebuilder_test.go` (+249 net new), `pkg/report/trivy.go`, plus the `GoVCSURL` field plumbing.

### Premise correction

Original SCR premise (Revision 1): *"Copa v0.14.0 includes PR #1546 → drop the fork."*

Actual reality: **v0.14.0 contains a stripped-down version of PR #1546. The verity-org fork has 12 additional commits that handle real production cases v0.14.0 cannot. Dropping the fork would regress cockroach, mongo-tools, kyverno-distroless, and prom-config-reloader patching.**

The Phase B regex breakage on `_is_go_rebuild_failure()` is downstream of this: failure modes the fork prevents are exactly the ones v0.14.0 surfaces.

### New direction

Keep the fork. Rebase `verity-org/copacetic feat/go-vcs-resolution` onto upstream `project-copacetic/copacetic main` (now past v0.14.0). Re-pin `go.mod` to the new fork HEAD pseudo-version. This:

- Preserves the 12 fork commits' production capabilities.
- Picks up Copa v0.14.0's other features (Python venv #1485, RPM chroot #1473, Arch pacman #1467, bulk cross-registry #1475) and bug fixes (#1530, #1516, #1532, #1525).
- Keeps the `replace` directive in `go.mod` (does NOT drop it).
- Resets the `replace` target to the new pseudo-version after rebase.



# SCR-2026-05-06-001 — Upgrade Copa to v0.14.0 and drop verity-org/copacetic fork

## Context

Verity bundles Copa as a Go library (`internal/patch/patch.go` imports `github.com/project-copacetic/copacetic/pkg/patch`). The current pin is `v0.13.1-0.20260422213235-21047038c9fe` with a `replace` directive redirecting to `github.com/verity-org/copacetic` on the `feat/go-vcs-resolution` branch. This fork exists solely to carry the not-yet-merged fallback source resolution for stripped/distroless Go binaries.

Copa **v0.14.0** was released on 2026-05-05 and includes [PR #1546](https://github.com/project-copacetic/copacetic/pull/1546) — the exact fork change. The codebase already documents the planned removal in two places:

- `internal/patch/patch.go:105` — *"The replace directive is dropped once #1546 merges upstream and verity re-pins to a tagged release."*
- `.github/scripts/patch-image.sh:13-17` — *"the replace directive is dropped once upstream copa PR #1546 merges."*

This SCR cashes in that planned cleanup.

## Goals

Bring Verity onto upstream Copa `v0.14.0` with **no behavioral regressions** in the patch pipeline across the 43-image catalog × 2 platforms (linux/amd64, linux/arm64).

## Acceptance Criteria (Revision 2)

- **AC-1** `verity-org/copacetic feat/go-vcs-resolution` is rebased onto upstream `project-copacetic/copacetic main` (a commit at or past v0.14.0). All 12 fork commits preserved (or condensed if equivalent upstream changes exist — captured in PO's rebase notes). Pushed to origin with `--force-with-lease`.
- **AC-2** `go.mod` `replace github.com/project-copacetic/copacetic => github.com/verity-org/copacetic <new-pseudo-version>` directive points at the new rebased HEAD. `require` line for `project-copacetic/copacetic` updated to a v0.14.0-or-later tag/pseudo-version that matches the rebased fork's base.
- **AC-3** `go build -o verity .` succeeds. `go test ./...` passes 100%.
- **AC-4** Comments in `internal/patch/patch.go` and `.github/scripts/patch-image.sh` are updated to reflect the new state: fork still active, but rebased onto post-v0.14.0; no PR-pending language.
- **AC-5** The retry pattern set in `patch-image.sh::_is_go_rebuild_failure()` is re-validated against the **rebased fork's** log output (NOT raw v0.14.0 — Phase B-2 already proved raw v0.14.0 breaks the pattern set). Update only if rebased-fork output differs from current main behavior. Evidence: log samples.
- **AC-6** A staging dry-run of `orchestrator.yaml` against the 5-image subset (`cockroachdb/cockroach`, `mongodb/mongodb-community-server`, `kyverno/kyverno`, `prometheus/prometheus-config-reloader`, `nginx`) produces patched images with **CVE-after ≤ CVE-after on the last main run** for those same images. **Cockroach must successfully patch** (it currently fails on raw v0.14.0; the rebased fork should restore working behavior).
- **AC-7** `ARCHITECTURE.md` Components table entry for **Copa** is updated to reference: rebased fork on upstream v0.14.0+ base, fork-specific capabilities (synthetic binary fallback, Trivy-target fallback, OCI label resolution), and the v0.14.0 features picked up.
- **AC-8** A single atomic commit + PR lands the `go.mod`/`go.sum` re-pin, comment updates, and doc updates together. Evidence packet (`evidences/`) is gitignored, NOT committed. `.codenomad/` and `.nomadworks/` are gitignored in the same commit. PR description links to this SCR with revision history.

## Out of Scope (Deferred)

Captured for future SCRs — explicitly **not** done here:

- **Python venv patching adoption** (Copa #1485). Would expand the catalog and require per-image `pkgPath` config in `copa-config.yaml`.
- **RPM chroot patching adoption** (Copa #1473). Would re-enable previously-skipped distroless RPM images.
- **Patch summary output integration** (Copa #1517). Would feed richer fields into `copa_*` honeycomb attrs.

## Implementation Plan (Revision 2 — single slice `core`)

### Phase D-1 (PO-driven): Rebase the fork

In a separate clone of `github.com/verity-org/copacetic`:

1. Add upstream remote: `git remote add upstream https://github.com/project-copacetic/copacetic.git`
2. Fetch: `git fetch upstream`
3. Checkout fork branch: `git checkout feat/go-vcs-resolution`
4. Rebase: `git rebase upstream/main`
5. Resolve any conflicts (most likely in `pkg/langmgr/golang.go` — fork's major rewrite vs upstream's PR #1546 baseline; in `pkg/types/options.go` — both add `GoVCSURL`; in `pkg/patch/single.go` — call signature drift).
6. Local sanity: `go build ./... && go test ./...` inside the copacetic clone (does not need to pass everything; verify the fork's added tests still pass).
7. Push: `git push --force-with-lease origin feat/go-vcs-resolution`.
8. Capture the new HEAD SHA + commit date — needed for the new `go.mod` pseudo-version.

### Phase D-2 (delegated to subagent): Reset and re-pin

1. Revert Phase A's staged changes on `chore/copa-0.14-upgrade` that dropped the `replace` directive (those were premised on the wrong direction).
2. Update `go.mod`:
   - `require github.com/project-copacetic/copacetic <v0.14.0-or-pseudo-version-matching-rebase-base>`
   - `replace github.com/project-copacetic/copacetic => github.com/verity-org/copacetic <new-pseudo-version-from-D-1>`
3. `go mod tidy`.
4. `go build -o verity .` + `go test ./...` (AC-3).
5. Update comments in `internal/patch/patch.go` `GoVCSURL` doc and `.github/scripts/patch-image.sh` header — describe rebased-fork state without PR-pending language (AC-4).

### Phase D-3 (delegated to subagent): Local smoke + regex re-validation

1. Re-run smoke against `cockroachdb/cockroach` and `prometheus/prometheus`. Capture logs.
2. Compare against pre-Phase-A behavior (which was the working fork). Cockroach should now succeed (or fail in the same way it did pre-Phase-A, but NOT the v0.14.0 `no modules specified` way).
3. Re-validate `_is_go_rebuild_failure()` regex against new logs. If rebased fork preserves legacy log surface → no regex change needed. If anything leaked through from upstream's PR #1516 / #1530 → minimal targeted regex update.

### Phase D-4 (PO-driven): Staging dispatch

1. `git push -u origin chore/copa-0.14-upgrade`.
2. `gh workflow run orchestrator.yaml --ref chore/copa-0.14-upgrade` against the 5-image subset.
3. Capture run summary + CVE diff (logs stay in local-only `evidences/`).

### Phase D-5 (delegated to subagent): Doc updates + atomic commit + PR

1. Update `ARCHITECTURE.md` Components table — Copa row.
2. Add `evidences/`, `.codenomad/`, `.nomadworks/` to `.gitignore`.
3. Atomic commit. Conventional Commits subject: `chore(deps): SCR-2026-05-06-001 rebase copa fork onto v0.14.0+ and re-pin`.
4. Rebase on `origin/main`. Open PR with the SCR linked + revision history.
